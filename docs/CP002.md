# CP002 — Configurable, explainable job scoring

## What changed
Adds a read-only endpoint:
`GET /api/jobs/recommendations?profile=senior`

Profile IDs: senior, graduate, nurse, secretary. Unknown ID returns 404; missing
profile returns 400. Empty storage returns an empty list. Existing CP001 discovery,
listing and database schema are unchanged. Recommendations do not discover or save jobs.

## Configuration
Edit `src/main/resources/candidate-profiles.properties` and restart. Candidate
metadata (occupation, experience level, skills) describes the candidate; explicit
rules determine scores. Skills are NOT silently converted into inferred experience
or qualification claims. Update both metadata and rules when tailoring a profile.
The graduate/nurse/secretary profiles are illustrative, not verified personal profiles.

Each profile has indexed rules with label, field, kind, weight and terms:
- Fields: TITLE, DESCRIPTION, LOCATION, WORK_MODE, CONTRACT_TYPE.
- PREFERENCE: earns positive points if any alias matches, at most once per rule.
- PENALTY: deducts points if any configured phrase matches.
- EXCLUSION: flags EXCLUDED_BY_PROFILE, independent of the numerical score.

Text matching is case-insensitive, whitespace-normalised and uses word boundaries.
Java does not match JavaScript. It is literal phrase matching, not semantic analysis.
It does not understand negation: for example, "Java not required" still mentions Java.
The commercial-Go penalty recognises the specific configured requirement phrases;
other wording requires new aliases. "Go can be learned" is not penalised.
No claim of reliable arbitrary advert interpretation is made.

Score = round(100 * clamp(earned points, 0, possible points) / possible points).
Possible points are the sum of PREFERENCE weights; penalties deduct raw points.
All criteria, including missing evidence, appear in reasons. A score is a relative
preference indicator under one profile, NOT a hiring probability or a percentage
of verified requirements. Scores from different profiles are not calibrated.
Excluded results remain visible but sort last; others sort by descending score,
then job ID for deterministic ties.

Expected senior scores for CP001 fixtures: Java Technical Lead 90, Senior Java
Engineer 75, Go Backend Engineer 0. The graduate profile scores the same senior
fixtures at zero; a separate graduate test fixture with Java/training scores 90.
This honestly shows that the current mock catalogue contains no graduate role.

## Eligibility
Without an exclusion, eligibility is NOT_ASSESSED. A nurse example can score highly
for title/patient care without verifying NMC registration. Credentials, salary,
right-to-work and other mandatory requirements need structured job requirements,
candidate evidence and a separate eligibility evaluator in a later ticket.
Do not interpret absence of an exclusion as eligibility.

## Test and use
Run `mvn test`: 11 new tests plus the 8 CP001 tests = 19 expected.
Start with `mvn spring-boot:run`. Populate only if needed:

```bash
curl -X POST http://localhost:8080/api/jobs/discover
curl 'http://localhost:8080/api/jobs/recommendations?profile=senior'
curl 'http://localhost:8080/api/jobs/recommendations?profile=graduate'
```

Stop any old app before restarting so the new endpoint is loaded.
Profile editing is configuration-only in CP002. No profile CRUD, user accounts,
authentication, AI integration or schema migrations are added. Keep localhost binding.
